## Development Status

### Changes to the Authentication System

Last year I wrote an article titled [The Pitfalls of Magic Link Authentication](https://zenn.dev/chorkaichan/articles/78b89eab08f55d), and this is the proper fix for that problem.

Firebase also has other issues, like the one described in [My Struggle with the "Unable to process request..." Error in Firebase Authentication](https://zenn.dev/chorkaichan/articles/09373b26ee2a4c), so I'd been wanting to switch away from it sooner rather than later.

This time I decided to go with [AWS Cognito](https://aws.amazon.com/jp/cognito/). I'm also dropping email link authentication, so sign-in will now be password-based.

I also took this opportunity to drop Twitter and Facebook login. For Android/iPhone users, Google/Apple login should be plenty, and I didn't think supporting Twitter/Facebook login was worth the unnecessary maintenance risk. (With Twitter/Facebook login, if someone registered their account with a phone number, we can't get their email address. Not having to handle that case makes the logic simpler, too.)

Switching to AWS also fixed the problem where emails took a long time to arrive during email link authentication. Signing in is gradually getting easier.

### DB Migration

Since I'm no longer using Firebase Authentication, the DB also needed to move to a different service.

As decided in the DB selection in [last November's post](https://chorkaichan.github.io/en/blog/202111-late), I'm going with MongoDB. Responses are quite fast, and the time it takes to render pages has gone down as a result (though since every page except My Page and the admin pages has its HTML generated in advance, you won't notice much of a difference...). Security has also improved significantly (I'll skip the details).

### A Library for Parsing Phone Numbers

I made a library called [jp-phone-parser](https://github.com/chorkaichan/jp-phone-parser), which parses Japanese phone numbers, including partial strings, into a delimited format.

If you want to attach it to an input via a selector or use it as a React component, there's [Cleave](https://github.com/nosir/cleave.js/), but since I'm currently using [Chakra UI](https://chakra-ui.com/), I wanted a simple parsing library if possible, so I built one. It's super lightweight and I'm happy with it, but given that super handy tools like the one above exist, I think it's mainly for people who fall into the same edge case as me.

It's tested against every phone number pattern in use, so it works without any problems. Feel free to use it if you like.
